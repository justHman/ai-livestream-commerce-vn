# Service-owned v1 contract artifacts

Service-owned generated API contracts (OpenSpec 1.53-1.54). There is no
repository-root `contracts/` registry: each artifact lives beside its
owner, regenerated deterministically by `scripts/contracts/generate.py`
and drift-checked by `scripts/contracts/check.py` (CI gate).

## Artifacts and owners

| Artifact | Owner | Generation |
|----------|-------|------------|
| `backend_service/contracts/v1/openapi.json` | backend | `backend.main:app` OpenAPI, v1 paths only |
| `backend_service/contracts/v1/websocket/control.schema.json` | backend | hand-authored (see below) |
| `backend_service/contracts/v1/websocket/platform.schema.json` | backend | hand-authored (see below) |
| `llm_service/contracts/v1/openapi.json` | llm | `llm.main:app` OpenAPI |
| `tts_service/contracts/v1/openapi.json` | tts | `tts.main:app` OpenAPI |
| `avatar_service/contracts/v1/openapi.json` | avatar | `avatar.main:app` OpenAPI |

FastAPI does not serialize WebSocket routes into its OpenAPI document
(`_get_api_route_for_openapi` in fastapi 0.141 returns `None` for
`WebSocketRoute`), so the two WS channels are hand-authored JSON Schemas
modeled on the backend `application` event models and the workbench WS
contract (verified MATCH in cluster 1.42-1.49). They must be updated by
hand when an event shape changes; `check.py` treats them as stable and
fails on manual drift only through the committed-file diff (they are
committed artifacts, regenerated byte-identically by the generator).

## Consumer map

A changed artifact must trigger only its owner's and known consumers'
checks (`scripts/contracts/check.py --scope <owner>` implements this).

| Artifact | Consumers | Triggered on change |
|----------|-----------|---------------------|
| backend `openapi.json` | backend tests, workbench (`workbench/src/api.ts`, smoke) | backend + workbench checks |
| backend WS `control.schema.json` | backend, workbench control client (`workbench/src/websocket.ts`) | backend + workbench checks |
| backend WS `platform.schema.json` | backend, workbench platform client | backend + workbench checks |
| llm `openapi.json` | backend LLM client contract tests (`backend/application/clients/llm/`) | llm + backend checks |
| tts `openapi.json` | backend TTS client contract tests (`backend/application/clients/tts/`) | tts + backend checks |
| avatar `openapi.json` | backend avatar client contract tests (`backend/application/clients/avatar/`) | avatar + backend checks |

Workbench is a frontend app; its checks are wired in the 1.59 CI matrix.
`check.py --scope` semantics: `--scope backend` checks backend artifacts
only; `--scope llm|tts` checks the model-service artifact plus the backend
openapi (because the backend clients consume those contracts);
`--scope avatar` checks avatar only (no backend openapi dependency today).

## Determinism

- JSON serialization: `sort_keys=True`, `indent=2`, trailing newline.
- No server URLs (`servers` removed), no timestamps.
- `generate.py` rerun produces byte-identical files (verified by hash).
- Operational health is excluded: `/health/live`, `/health/ready` and
  their versioned aliases never appear in a v1 artifact. The authenticated
  backend `GET /api/v1/admin/health` deep-diagnostics route is retained —
  design.md keeps detailed operator diagnostics under the backend v1 admin
  resource; it is not an operational health probe.

## Usage

```bash
# Regenerate all artifacts
PYTHONPATH=<4 service src dirs> uv run --project services/product/backend_service \
  python scripts/contracts/generate.py

# Drift check (CI gate; exit non-zero on ANY diff)
PYTHONPATH=<4 service src dirs> uv run --project services/product/backend_service \
  python scripts/contracts/check.py

# Scope a check to one owner + its consumers
PYTHONPATH=<4 service src dirs> uv run --project services/product/backend_service \
  python scripts/contracts/check.py --scope llm
```
